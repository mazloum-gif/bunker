# Бункер — Telegram Mini App

Многопользовательская игра «Бункер» прямо в Telegram: обсуждение → голосование → выбор вещей → катастрофа → следующий раунд.

## Что внутри

- **Бот** (long polling) с командами `/start`, `/new [название]`, `/open`.
- **Mini App** — веб-интерфейс игры с фазовым движком, чатом в бункере и голосованием.
- **Проверка подписи Telegram** (`initData` через HMAC-SHA256) на каждом API-запросе — подделать игрока нельзя.
- **CORS** разрешён для Telegram-клиентов (RSC `https://*.telegram.org`).
- **Автоопределение HTTPS-адреса**: Render проксирует `X-Forwarded-Proto`, поэтому внешний URL определяется сам (или задаётся `PUBLIC_URL`).
- **Постоянное хранилище**: Render Disk `/var/data`, состояние игр в `games.json`.

## Деплой на Render (1 клик)

Кнопка в README репозитория: **Deploy to Render**.

1. Жмём кнопку → Render создаёт сервис из `render.yaml`.
2. В поле `BOT_TOKEN` вставляем токен от **@BotFather**.
3. Ждём деплой (~2–3 минуты) и получаем адрес вида `https://bunker-xxxx.onrender.com`.

Токен от BotFather в чат не кидаем — только в поле формы Render.

## Привязка Mini App к боту

1. В Render копируем адрес сервиса (https).
2. @BotFather → `/newbot` → `/setmenubutton` → выбираем бота → вставляем этот URL.
3. В группе: `/new Название игры` — бот создаёт игру, игроки жмут кнопку и заходят в Mini App.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Токен Telegram-бота | — (без него работает только Mini App) |
| `PORT` | Порт сервера | `3000` |
| `PUBLIC_URL` | Внешний HTTPS-адрес, если автоопределение не подходит | авто (`X-Forwarded-Proto` + `Host`) |
| `DATA_DIR` | Каталог для постоянного хранилища | `./data` |

## Локальный запуск

```bash
npm install
BOT_TOKEN=123:ABC node server.js
```

Проверка: `GET /api/health` → `{"ok":true,"bot":true}`.
